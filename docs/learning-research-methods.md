# Learning & Research: Tricks 76-88

The depth of your learning determines the quality of your thinking.

## 13 Learning & Research Techniques

### 76. Summarize Research Papers
**Extract essence** from dense academic papers.

**Paper summary template:**
1. Title & authors: [What is this]
2. Main research question: [What are they trying to find out]
3. Methods: [How did they study it]
4. Key findings: [What did they discover]
5. Implications: [Why does it matter]
6. Limitations: [What's this study NOT showing]
7. How it applies to [Your work]: [Why you care]

**Example:**
```
Summarize this research paper: [Link or upload]

I'm reading this because: [Your reason]
My background: [What I already know]

For the summary, include:
- What they studied (in plain English)
- How they did it (methodology)
- What they found (key results)
- Why it matters (implications)
- How it relates to [your field]

Make it 1 page, scannable (bullets, short paragraphs).
```

### 77. Create Study Guides & Flashcards
**Build materials** that make studying efficient.

**Study guide structure:**
1. Key concepts (definitions, clear explanations)
2. Examples (real-world illustration)
3. Practice questions (with answers)
4. Common mistakes (what students get wrong)
5. Cheat sheet (one-page reference)

**Flashcard structure:**
- Front: Question or concept
- Back: Concise answer (2-3 sentences max)
- Include examples
- Organize by difficulty

**Example:**
```
Create a study guide for [topic/course].

Subject: [What you're studying]
Level: [Difficulty: intro/intermediate/advanced]
Exam/goal: [Why you're studying]

Create:
1. Key terms (25-30, with definitions)
2. Main concepts (5 big ideas explained simply)
3. Practice questions (10, with detailed answers)
4. Common confusions (things people get wrong)
5. One-page cheat sheet (everything you need to remember)

Format flashcard-style questions on the main concepts.
Make answers concise but complete.
```

### 78. Generate Quiz Questions
**Create questions** that test real understanding, not memorization.

**Question types:**
- Recall: "What is X?" (basic facts)
- Understanding: "Explain how X works" (deeper grasp)
- Application: "How would you use X in [situation]?" (real-world)
- Analysis: "Compare X and Y" (critical thinking)
- Synthesis: "How does X relate to Y?" (connections)

**Example:**
```
Generate 20 quiz questions for [topic].

Level: [Difficulty]
Format: [Multiple choice / short answer / essay]
Focus: [What they should know]

Include mix of:
- Factual recall (5)
- Understanding (7)
- Application (5)
- Critical thinking (3)

Provide answer key with explanations.
```

### 79. Explain Complex Theories
**Translate abstract concepts** into understandable explanations.

**Explanation structure:**
1. Core idea (simplify to one sentence)
2. Why it matters (context, relevance)
3. Concrete example (real-world illustration)
4. How it works (step-by-step)
5. Counterexample (when it doesn't apply)
6. Real-world application (how it's used)

**Example:**
```
Explain [complex theory/concept] like I have zero background.

I need to understand:
- The core idea (boil it down)
- Why it matters (why should I care)
- How it works (step-by-step process)
- Real examples (show me in action)
- Where it's applied (how the world uses it)

Use analogies from everyday life. 
No jargon. Make it feel intuitive, not academic.
```

### 80. Compare Philosophies
**Analyze different viewpoints** and their implications.

**Philosophy comparison structure:**
1. Philosophy A: Core belief
   - Key premise
   - Who believes this
   - Strengths (why it's appealing)
   - Weaknesses (problems with this view)
2. Philosophy B: Core belief
   - (same structure)
3. Where they agree
4. Where they disagree
5. Which is more useful/true and why

**Example:**
```
Compare [Philosophy A] vs [Philosophy B].

What's the core belief of each?
Who advocates for each view?
What are the strengths of each?
What are the weaknesses?

Create a comparison that shows:
- Side-by-side beliefs
- Real-world implications
- Where they agree
- Where they disagree
- Which is more compelling and why
```

### 81. Build Curated Reading Lists
**Create organized collection** of best resources on a topic.

**Reading list structure:**
1. Foundation (start here for beginners)
   - Resource 1: [Book/article], why it matters
2. Deeper understanding
   - Resources that build on foundation
3. Expert level
   - Advanced materials
4. Practitioner perspective
   - Real-world application
5. Opposing viewpoints
   - Alternative perspectives

**Example:**
```
Build a reading list for learning [topic].

Starting point: [Your knowledge level]
Goal: [What you want to understand]
Learning style: [Books/articles/videos/courses]
Time available: [How much you can commit]

Create organized list with:
1. 3 foundational resources (start here)
2. 5 intermediate resources (go deeper)
3. 3 advanced resources (expert level)
4. 2 perspectives challenging the mainstream
5. 1 practical guide (how to apply it)

For each:
- Title & author
- Why it matters
- How it fits in the learning journey
- Time commitment
```

### 82. Translate Abstract Concepts
**Make theoretical ideas concrete** and understandable.

**Translation process:**
1. Core principle (what's the essence)
2. Why it's hard to understand (common confusion)
3. Analogy (relatable comparison)
4. Concrete example (real situation)
5. Step-by-step breakdown (how it works)
6. Common mistakes (what people misunderstand)

**Example:**
```
Make [abstract concept] actually understandable.

Concept: [What you need explained]
Audience: [Who needs to get this]
Context: [Why they need to understand]

Create explanation that includes:
- Simple one-sentence definition
- Why it confuses people
- 2 different analogies (from different domains)
- Real example from [specific industry/context]
- Step-by-step breakdown
- Common misunderstandings

Make it so clear that a teenager could explain it to others.
```

### 83. Socratic Dialogue Mode
**Use questioning to deepen understanding** instead of providing answers.

**Socratic dialogue structure:**
1. Clarify the question (what are we really asking?)
2. Explore assumptions (what are you assuming is true?)
3. Test with examples (does this hold in [situation]?)
4. Look for contradictions (does this conflict with [other idea]?)
5. Draw conclusion (what does this teach us?)

**Example:**
```
Use Socratic dialogue to help me understand [topic].

I think [my current understanding].
I'm confused about [specific confusion].

Instead of just explaining, help me think deeper by:
- Asking questions that reveal my assumptions
- Having me test my thinking against examples
- Finding where my thinking might be incomplete
- Leading me to a deeper understanding

Let the dialogue unfold naturally.
```

### 84. Fact-Check Claims
**Verify information** and distinguish fact from opinion.

**Fact-checking structure:**
1. Claim: [What's being said]
2. Source check: [Where's it from, credible?]
3. Evidence: [What evidence supports this?]
4. Counter-evidence: [What contradicts this?]
5. Expert opinion: [What do credible experts say?]
6. Conclusion: [True, partially true, false, unknown?]

**Example:**
```
Help me fact-check these claims: [List claims]

For each claim:
- Rate credibility of source
- Find supporting evidence
- Find contradicting evidence
- What do credible experts say
- Overall verdict (true/false/partial/unverified)

Include:
- Best sources to verify
- Red flags you notice
- What seems most likely to be true
```

### 85. Simplify Jargon
**Translate technical language** into plain English.

**Jargon simplification:**
1. Technical term: [What it's called]
2. Simple definition: [What it means in plain English]
3. Analogy: [What's it like]
4. Example: [Where you'd see this]
5. Why it matters: [Why should you care]

**Example:**
```
Simplify these terms from [field]:
[List of jargon]

For each:
- Plain English definition (one sentence)
- Analogy (what's it similar to)
- Real example (where you'd encounter it)
- Why the technical term exists (what does it convey)

Make me feel like I understand these terms, not intimidated by them.
```

### 86. Teach Skills Step-by-Step
**Create clear progression** for learning new abilities.

**Skill teaching structure:**
1. Overview: What you're learning and why
2. Prerequisites: What you should know first
3. Step 1: Foundational concept
   - Explanation
   - Example
   - Practice exercise
4. Step 2: Build on step 1
5. (Continue as needed)
6. Integration: How to use together
7. Common mistakes: What people get wrong
8. Practice project: Apply the whole skill

**Example:**
```
Teach me [specific skill].

My background: [What I already know]
My goal: [Why I'm learning this]
Time: [How much I can dedicate]

Create lesson that:
1. Explains why this skill matters
2. Shows prerequisites (what I need first)
3. Breaks it into 4-5 small steps (building blocks)
4. For each step: explanation, example, exercise
5. How to combine steps into full skill
6. What usually trips people up
7. A practice project to apply everything

Make it hands-on. I learn by doing.
```

### 87. Analyze Multiple Sources
**Synthesize information** from many sources into coherent understanding.

**Multi-source analysis:**
1. Source A: [Main point]
   - Key findings
   - Credibility check
2. Source B: [Main point]
3. Source C: [Main point]
4. Where they agree (common ground)
5. Where they disagree (conflicts)
6. Synthesis (what's most likely true)
7. Gaps (what's still unknown)

**Example:**
```
I've read/researched [topic] from multiple sources.

Source 1: [Title/author] says [main point]
Source 2: [Title/author] says [main point]
Source 3: [Title/author] says [main point]

Help me:
- Understand each perspective
- Find where they agree
- Identify their disagreements
- Evaluate which is most credible
- Synthesize into coherent understanding
- Identify what's still unclear

Make sense of the conflicting information.
```

### 88. Create Learning Roadmap
**Map your learning journey** with clear milestones.

**Learning roadmap structure:**
1. Goal: [What you want to learn and why]
2. Starting point: [What you know now]
3. Phase 1 (Weeks 1-4): [Foundation]
   - Topics: [What you'll learn]
   - Resources: [Materials to use]
   - Projects: [How to practice]
4. Phase 2 (Weeks 5-8): [Intermediate]
5. Phase 3 (Weeks 9-12): [Advanced]
6. Milestones: [Checkpoints to verify progress]
7. Time commitment: [Hours per week]
8. Success criteria: [How you know you've learned]

**Example:**
```
Create a learning roadmap for [skill/topic].

Goal: [What I want to be able to do]
Starting point: [My current knowledge]
Time available: [Hours per week]
Learning style: [How you learn best]
Constraints: [What you can't do]

Create a 12-week roadmap with:
1. 3 phases (build progressively)
2. For each phase: topics, resources, projects
3. Weekly milestones (how to track progress)
4. Success metrics (how to know you've learned)
5. Resource list (books, courses, communities)

Make it realistic and specific.
```

## Learning Decision Tree

**Do you need to understand deeply?**
→ **Explain complex theories** + **Socratic dialogue mode**

**Do you need to master quickly?**
→ **Learning roadmap** + **Create study guides**

**Are you overwhelmed by information?**
→ **Synthesize multiple sources** + **Simplify jargon**

**Do you need credentials/test prep?**
→ **Generate quiz questions** + **Create study guides**

**Do you want to research well?**
→ **Summarize research papers** + **Build curated reading lists**

## Real-World Example

**Weak learning request:**
```
Help me understand machine learning.
```

**Strong learning request:**
```
I want to understand machine learning well enough to 
have intelligent conversations about it.

Background:
- Math level: [Your math knowledge]
- Tech knowledge: [Programming/technical experience]
- Why I need this: [Your goal]
- Time: [How much you can dedicate]

I get confused about:
- How it differs from traditional programming
- What "training" actually means
- When to use different algorithms

Create:
1. Learning roadmap (8-week progression)
2. Foundation concepts (explained simply)
3. Key topics to master (5-7 main ideas)
4. For each topic: explanation + real example
5. How it all connects (system-level view)
6. Common misconceptions (what I might get wrong)
7. Resources to go deeper
8. Questions I can ask to test my understanding

Focus on intuitive understanding, not mathematical rigor.
```

**The difference:** Clear context + specific confusions + structured progression = actual deep learning instead of surface-level knowledge.
